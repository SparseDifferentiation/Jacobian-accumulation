Conclusions
-----------
1. The extraction content of path E is E1 alone (0.61 s at n=800): the user
   hand-assembles (H, A), i.e. does the canonicalization themselves, outside
   CasADi.  That is declared-structure extraction -- the other paradigm in
   this comparison -- not a faster way for CasADi to extract; in the
   benchmark it would put the lowered matrices outside the timer entirely
   (prohibited by the fairness rules).
2. E2 is NOT near-zero: qrqp's structural setup (KKT sparsity assembly +
   symbolic factorization analysis) on the dense declared pattern costs
   30.8 s at n=800, scaling ~x7 per size doubling.  So even after the user
   has done all the extraction work by hand, CasADi's conic front-end spends
   7x the harness's entire A-path extraction time (4.4 s) on dense-block
   structure before any solve.  This is solver init, outside the extraction
   comparison's scope, but it shows the conic-with-DM route is not the free
   lunch the advice suggests.
3. C (qpsol ctor) minus E2 (conic ctor) ~= 122 s at n=800, matching B/D: the
   AD extraction inside qpsol is the hessian-path cost, as concluded on
   2026-07-16.  The harness A-path remains the fastest CasADi extraction
   route at every size.
4. "Use DM for constants" is already the harness default (every constant in
   the user's data is a DM in casadi_compare.py), and DM does not shortcut
   jacobian(): constant-DM vs parametric-MX A cost the same
   (results_probe_hierarchical_trace_20260719.txt).
