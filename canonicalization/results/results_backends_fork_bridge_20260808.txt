Diff-engine fork: pinned-CPP bridge run (companion to the upstream 1.9.2 sweep)
==============================================================================
Date:    2026-08-08
Machine: MacBook Pro (15-inch, 2018), 6-core Intel i7-8850H @ 2.60GHz, 16 GB,
         macOS 15.7.7. BLAS pinned to 1 thread.
Env:     .venv -- cvxpy 0.1.0.dev3996+gca08a26d1 (Transurgeon fork,
         pr-c-resolve-caching), sparsediffpy 0.7.0 LOCAL DEV BUILD (commit
         9db427c), Python 3.14, numpy 2.4.6, scipy 1.17.1.
         Engine version was asserted before the run: PyPI 0.6.0 would have
         invalidated every warm re-solve.

Purpose
-------
1. VERSION BRIDGE. The *_ND (ignore_dpp) columns can only be measured on stock
   upstream cvxpy, so comparing them against this fork's DIFFENGINE column is a
   cross-version comparison. This run measures CPP/SCIPY/COO on the DPP path
   here, so the fork-vs-upstream offset is known. Result: the fork is
   consistently 1.03x-1.21x SLOWER for the same backend on the same problem
   (Cajas 1.11, Murray 1.17, Yitzhaki 1.19, CVaR 1.08, ParamCone 1.03,
   ParamSmall 1.04). The offset is systematic and small relative to the effects
   being reported, so the cross-version comparison is sound -- and conservative,
   since it works against the engine.
2. The CPP_DEFAULT column, which passes NO canon_backend, reproducing what the
   older published tables actually measured.

The CPP mislabelling, demonstrated
----------------------------------
With no canon_backend, cvxpy silently substitutes COO once total parameter size
reaches DPP_PARAM_THRESHOLD (1000). On the parametric problems CPP_DEFAULT
tracks COO, not CPP:
    ParamConeMatrixStuffing   CPP_DEFAULT 0.2718  COO 0.2842  CPP 3.3539
    ParamSmallMatrixStuffing  CPP_DEFAULT 0.4182  COO 0.4247  CPP 8.1883
and the old published cells (results_backends_all_20260724_repl.txt) were
0.2876 and 0.4466 -- i.e. COO. True pinned CPP is 12-18x larger. On the
parameter-free problems CPP_DEFAULT == CPP as expected (Cajas 22.66 vs 22.67).

ConvexPlasticity: stock cvxcore is UNMEASURABLE on this fork
------------------------------------------------------------
The problem is not DPP under the chain's predicate, so an explicit canon_backend
raises ValueError -- CPP, SCIPY and COO all ERR. Only DIFFENGINE (2.0221),
DE_DPP (2.0523) and CPP_DEFAULT (2.0531) return, and CPP_DEFAULT == DIFFENGINE
because passing no backend force-routes to the engine. The old table's
"CPP 2.1382" baseline for this row was therefore the diff engine compared
against itself. Stock upstream cvxcore does the same extraction in 0.3586 s,
i.e. the engine is ~5.6x SLOWER here (~4.7x after the version offset). Cause is
already known and now quantified: the engine emits P with 9,048,000 stored
entries for a true nnz of 33,000 (274x zero padding); upstream emits exactly
33,000.

Gaps
----
* ParametrizedQPBenchmark: skipped via BENCH_SKIP (killed the upstream run).
* SimpleFullyParametrizedLPBenchmark: crashed/killed under pinned CPP here too,
  no Python exception -- the same cross-version failure described in the

timeout: 2400s/problem   solver=CLARABEL (uniform, for comparability)

Table 1 = COLD first-compile time (s) of each problem under each canon backend
  (fresh setup + get_problem_data per backend, since the chain cache key
  excludes canon_backend).
Table 2 = re-compile time (s) with changing parameters (parametric problems
  only), mean of 3, fresh instance per strategy.
The last column of each table is a configurable ratio (BENCH_RATIO,
BENCH_RATIO_WARM); <1 means the numerator is faster.

Targets (the get_problem_data kwargs each column selects):
  CPP/SCIPY/COO      explicit canon_backend, DPP path -- builds the
                     parameter->data TENSOR (only worth it across re-solves).
  CPP_ND/SCIPY_ND/   same backend with ignore_dpp=True: EvalParams bakes the
  COO_ND             parameters into constants, so the backend builds a plain
                     non-parametric matrix -- the SAME artefact the diff engine
                     produces, hence the like-for-like comparison. Upstream
                     cvxpy only: the fork rejects an explicit backend here.
  CPP_DEFAULT        no canon_backend at all. NOT the same as CPP: cvxpy
                     silently switches to COO once total parameter size >=
                     DPP_PARAM_THRESHOLD (1000). Kept only to replicate
                     results published before the CPP column was pinned.
  DIFFENGINE         ignore_dpp=True with no explicit backend (diff-engine fork).
  DE_DPP             explicit canon_backend=DIFFENGINE on the DPP path.
  dpp/diffengine/    warm strategies; nodpp_* are the ignore_dpp=True variants,
  de_cached/dpp_*/   where cvxpy sets uncached_param_prog and every re-solve is
  nodpp_*            a FULL recompile -- i.e. the cost of not having DPP.
'dpp?' is is_dpp() as the solving chain evaluates it (quad_form_dpp='qp' for
solvers that take a quadratic objective), which is what decides the branch --
not the bare problem.is_dpp() older tables reported.
